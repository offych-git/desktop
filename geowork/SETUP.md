# Deploy and hand off GeoWork

## Website build

From repo root:
```bash
cd geowork
npm install
npm run build
```

The site is Astro 7, statically rendered. A successful static build emits public blog pages and an XML sitemap. Node 24 is recommended.

## Netlify hosting

A Netlify project `geowork-preview` has been created, but connecting the repository and publishing the latest code still needs to be completed.

Connect GitHub repo `offych-git/desktop` to **that existing project**, then set:
- Base directory: `geowork`
- Build command: `npm run build`
- Publish directory: `dist`
- Production branch: `main`

Site environment variables (not secrets; public IDs):
- `PUBLIC_SANITY_PROJECT_ID=hixm4vas`
- `PUBLIC_SANITY_DATASET=production`

The Sanity Studio route `/admin/` is generated by the Astro integration when the project ID is configured. The previous GitHub-token Sveltia CMS has been removed completely.

**Before claiming:** the Sanity project is unowned and expires 72 hours after creation. Claim it before the deadline. After claim, invite client editors in Sanity with limited editorial permissions and allow CORS for the exact Netlify and future production origins, with credentials for Studio login.

New articles are static Astro pages. Configure a Sanity publish webhook to a private Netlify build-hook URL so CMS changes trigger a rebuild. Do not expose the build hook or a Sanity write token to the client-side app.

## Content

Three initial articles live under `src/content/blog/` as fallback until imported into Sanity; users cannot edit these legacy Markdown documents in Sanity yet. Publishing new articles happens in Sanity, independently from GitHub.

## Contact forms

The contact form uses Netlify Forms. Enable Forms on the actual published site and set email notifications to `contact@geowork.us`. The form is not confirmed until tested on the live site.
